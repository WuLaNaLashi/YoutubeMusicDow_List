第一次使用

环境要求

  • ffmpeg — 容器封装、元数据写入(不做有损编解码)。各平台安装命令见 故障排查。
  • deno — yt-dlp 依赖它解决 YouTube 的 JS 挑战;没有也可配置 node 兜底。
  • 能访问 YouTube — 境内需自备代理。
💡 小贴士  首次启动会自动跑环境自检(帮助 → 故障排查向导),缺什么会直接给安装命令。

音频策略

核心原则:不做任何有损二次转码。YouTube 给免费用户的音频流有两种容器:

  • .webm 内含 opus 编码(~160 kbps)— 默认优先,音质更好
  • .m4a 内含 AAC 编码(~128 kbps)

项目优先取 opus,用 ffmpeg -c copy 把 webm 重封装为 opus(Ogg 容器),bit-for-bit 保留,不重新编码。想要 mp3 见 FAQ。

⬇️ 下载

做什么:读歌单 → YT 搜索 → 筛选打分 → 下载 opus 流 → 嵌入封面/元数据。对应 CLI main.py。

歌单格式

每行一首歌,分隔符是最后一个 -(因为有些歌名含 -):

起风了-买辣椒也用券
そばにいるね (留在我身边)-青山黛玛 _ SoulJa
Monica-

缺艺人字段可只写 歌名-,但匹配精度会下降(被判为 ok_no_artist)。

操作要点

  • 测试模式:固定随机种子,可复现,验证环境用
  • 断点续传:中断后勾选,自动跳过 success.json 已成功项
  • 并发数:滑块调 1~10,默认 3;网速差就调小
  • 失败重试:失败列表在下载页底部,支持全部重试或勾选重试
⚠️ 重要  下载结果不能保证 100% 准确。1106 首实测:完美匹配约 66%、艺人别名疑似 27%、需 review 6%、真不匹配 1.3%。所以跑完务必去 匹配校验 页 review。

🔍 匹配校验

做什么:对比"你请求的"和"实际下到的",按 8 级分类,出报告。对应 CLI check_matches.py。

这是工具的质量闸。即使搜索下错了,这里会暴露给你。优先 review ❌ mismatch,其次 ⚠️ warn_title_diff。

  • ↗ YT:浏览器打开 videoId 人工核对
  • 📁:打开文件所在目录
  • ↻ 重下:删掉 success.json 该条目,重新搜索下载

分类含义详见 匹配分类体系。

🗂️ 文件整理

做什么:① 按分类挪进子目录 downloads/{cls}/(幂等);② 按内嵌元数据改名。对应 CLI organize_by_check.py + rename_by_metadata.py。

  • 挪文件:可选移动/复制,支持 dry-run 预览再 apply
  • 改名:把 mismatch/warn 的文件改成「真实艺人 - 真实标题」,让文件名和内容对上

🛠️ 转码 & 改名

opus → mp3

320 kbps CBR(libmp3lame 上限),保留封面与标签。输出进 {dir}/mp3/。对应 opus2mp3.py。

注意  opus→mp3 是有损→有损,会有音质损失。仅在设备不支持 opus 时用。

随机播放改名(红米音箱)

给文件名加随机前缀(如 a3b7_),让音箱按文件名排序实现"伪随机"播放。支持 number/letter/mixed 三种前缀,可 还原。

⚙️ 设置 / Cookies

Cookies 三种来源(重点)

  1. cookies.txt 文件(推荐,Linux 下最稳):手动上传 Netscape 格式文件
  2. 从浏览器提取:自动读 Chrome/Firefox/Edge 的 cookies(Windows/macOS 友好)
  3. 不使用:可能被要求认证,精度下降

所有来源都附"测试有效性"按钮——跑一次轻量请求验证。

过滤词

SKIP_KEYWORDS 命中即跳过(karaoke/伴奏/翻唱…),DEPRIORITIZE_KEYWORDS 降权(live/acoustic…,扣 15 分但不是必删)。改完对新下载生效,不影响已下载文件。

配置持久化

UI 改动写入 config.user.json,覆盖 config.py 默认值,不污染源码。CLI 启动也读它,两边互不干扰。

匹配分类体系

check_matches 把每首歌按以下规则归类。橙色行需重点 review:

标签含义触发条件
✅ ok艺人+标题都对artist=exact, title_sim ≥ 0.55
🟡 ok_no_artist歌单原始缺艺人,只能按标题判断requested 为空, sim ≥ 0.7
🔵 warn_alias_likely艺人字面不同但标题完全一致(罗马音/艺名差异,如 米津玄师↔Kenshi Yonezu)astat=none, sim ≥ 0.92
⚠️ warn_title_diff艺人对但标题差异大astat=exact, sim<0.55, 非子串/medley
⚠️ warn_partial_artist艺人字符仅部分相交astat=partial
⚠️ warn_no_artistYT 返回的艺人为空astat=no_matched
❌ mismatch艺人不同 + 标题也明显不同,需重下astat=none, sim<0.92

medley 检测:标题含 Medley/连环炮/串烧/组曲 或括号外 ≥2 个 /,会判为 mismatch,防止"金曲连环炮"因包含歌名被误判同曲。

已知限制(坦白告知)

  1. 歌单数据反向:部分条目艺人写在前歌名在后,YT 搜索容错通常能救,但 metadata 会反。
  2. 含 - 的艺人名(A-Lin、F.I.R.):解析器会切错,YT 容错常能救。
  3. 单字标题(溯、哇):子串检测被跳过,落到 mismatch,需人工 review。
  4. 跨语言同曲(金达莱花↔Azalea):同首歌但脚本无法自动识别,落到 warn_title_diff。
  5. 特定版本:用户写"DJ 阿卓版"但 YT Music 没有,只下到普通版。
  6. 音质上限受账号影响:无 Premium 上限是 opus ~160 kbps。
