# list_non_catalog.py — 找出非 YT Music 正版编录的歌

扫描 `downloads/` 下所有音频文件，区分哪些是 **YT Music 正版编录**（来自官方 *Topic* 频道）、哪些是**普通视频 fallback**（用户上传 MV、Live、翻唱等），生成报告 `logs/non_ytmusic_report.md`。

> 和 [check_matches.md](check_matches.md) 互补：`check_matches` 看「**下载到的是不是想要的歌**」，本工具看「**这首歌是不是正版音源**」。

---

## 一、命令行参数

```
usage: list_non_catalog.py [-h] [-o OUT] [--include-no-album]

可选:
  --include-no-album   把缺 album 字段的编录条目也列出来（可能是厂牌没填全）
  -o, --out OUT        报告输出路径，默认 logs/non_ytmusic_report.md
  -h, --help           查看帮助
```

### 关键参数说明

| 参数 | 作用 |
|------|------|
| `--include-no-album` | 默认只报告 `non_catalog`。加上后会把 `catalog_no_album`（是正版编录但缺 album 字段）也单独列一节，便于检查元数据完整性。 |
| `-o` | 自定义报告路径。默认 `logs/non_ytmusic_report.md`。 |

---

## 二、判定原理（金标准）

YT Music 的正版编录由后台自动的 *Topic* 频道发布，YouTube 自动生成的 description 里**一定**带这个签名：

```
Provided to YouTube by {厂牌名}
...
Auto-generated by YouTube.
```

非编录的普通视频（用户上传 MV、Live、翻唱）**不会有**这个签名。

脚本读音频文件的内嵌元数据，找 `synopsis` / `description` 字段里的这个签名：

| 字段命中 | 分类 |
|----------|------|
| 命中 `Provided to YouTube by` 或 `Auto-generated by YouTube`，且 album 字段非空 | ✅ `catalog` |
| 命中签名，但 album 字段空 | 🟡 `catalog_no_album`（少见，元数据没填全）|
| 没命中签名 | ❌ `non_catalog`（普通视频 / fallback）|
| 文件读不出来 | ⚠️ `unreadable` |

## 三、典型用法

### 1. 默认：生成报告

```bash
python src/list_non_catalog.py
```

输出：

```
Report: logs/non_ytmusic_report.md
  catalog=1024  catalog_no_album=12  non_catalog=70  unreadable=0
```

打开报告看 `non_catalog` 那一节。

### 2. 同时列出 catalog_no_album

```bash
python src/list_non_catalog.py --include-no-album
```

### 3. 输出到自定义路径

```bash
python src/list_non_catalog.py -o /tmp/catalog_check.md
```

## 四、报告结构

`logs/non_ytmusic_report.md`：

1. **总览**：各类数量统计
2. **判定方法**：解释签名机制
3. **❌ 非 YT Music 编录**（`non_catalog`）：每首展开，含文件名、标题、艺人、album、videoId、发布日期、synopsis 预览
4. **🟡 编录但缺 album**（仅 `--include-no-album` 时显示）
5. **⚠️ 无法读取 metadata**（如有）

每条 `non_catalog` 项的示例：

```markdown
### `某歌手 - 某 Live 版.opus`
- 路径: `downloads/warn_title_diff/某歌手 - 某 Live 版.opus`
- 标题: `某某歌 (Live at 某某演唱会)`  艺人: `某歌手`
- 专辑: ``（空）
- videoId: `xxxxxxx` · 发布日期: `20230512`
- synopsis 预览: `'Uploaded by ...'`（不是 Provided to YouTube by，说明是用户上传）
```

## 五、典型场景

### 场景 A：想知道某首歌是不是正版音源

跑完后看 `non_catalog` 分类。如果是普通视频，可能是 Live / MV / 翻唱版本，音质/版本可能不如正版编录。

### 场景 B：作为 check_matches 的补充

[check_matches.md](check_matches.md) 主要看「歌名/艺人对不对」，但即使歌名对得上，也可能是**用户上传的非编录版本**（音质差、有观众噪音、是 Live）。本工具帮你揪出这些。

### 场景 C：想替换非编录版本

发现 `non_catalog` 里有某首歌，想换成正版编录：
1. 在 YT Music 搜这首歌的正版 Topic 频道版本
2. 拿到 URL，用 [download_from_urls.md](download_from_urls.md) 重下
3. 删掉旧的非编录版本

## 六、和 check_matches 的区别

| 工具 | 判定维度 | 数据来源 |
|------|----------|----------|
| [check_matches.md](check_matches.md) | 「**歌对不对**」（标题/艺人字面相似度）| `logs/success.json` 里的请求 vs 匹配元数据 |
| **list_non_catalog** | 「**音源正版不正版**」（是不是 YT Music Topic 频道）| 文件**内嵌**的 synopsis/description 字段 |

两者正交：一首歌可以「歌对（ok）」但「非编录（non_catalog）」——比如 YT 搜索命中了某个用户上传的 Live 版本，歌名对、艺人对，但不是正版录音。

## 七、常见问题

### Q: synopsis 预览显示 `'Uploaded by ...'`

这是用户上传的视频，不是 YT Music 自动生成的 Topic 频道。属于 `non_catalog`。

### Q: 某首歌明显是正版，却被判 non_catalog

可能 ytmusicapi 当初没走 `filter="songs"` 搜索，或者 ytmusicapi 版本过旧。检查 [main.md](main.md) 日志里有没有 `ytmusicapi songs-search failed` 警告。

### Q: 想过滤掉非编录版本，重新下载正版

目前没有自动化流程。手动找正确 videoId，用 [download_from_urls.md](download_from_urls.md) 重下。

### Q: `unreadable` 是怎么回事

音频文件损坏或 mutagen 不支持的格式。检查文件完整性：

```bash
ffprobe -hide_banner "/path/to/file.opus"
```
