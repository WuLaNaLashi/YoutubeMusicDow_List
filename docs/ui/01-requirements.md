# YT_Music UI 需求文档

> 版本:v0.1  日期:2026-08-06  分支:`feat/ui-integration`
> 状态:草案,待用户确认

本文档把现有 CLI 工具链(见根 `README.md`)的功能,翻译成一份 UI 应具备的能力清单。
它是后续技术选型(`02-tech-stack.md`)、原型(`prototype/`)和开发的依据。

---

## 1. 背景

当前仓库是一个**命令行工具链**:11 个 Python 脚本,靠 `--test/--all/--resume/--apply` 等
flag 串联起"下载 → 校验 → 整理 → 改名 → 转码"的工作流。痛点:

1. 用户要在终端敲多条命令、记顺序、看日志文件。
2. 配置全靠手改 `src/config.py`(纯文本,易写错)。
3. cookies / 代理这类"环境性"配置,新用户最容易卡在这里。
4. 匹配质量校验报告是 markdown,要打开编辑器看,无法在结果上直接操作。
5. 没有运行态反馈:跑 1000 首时不知道进度、不知道当前在哪一首。

UI 的目标:**把这些能力收进一个跨平台图形界面,把"多步 CLI 工作流"变成"点击 + 实时反馈"。**

---

## 2. 目标用户与场景

| 角色 | 主要诉求 |
|------|----------|
| **新用户**(不熟 CLI) | 装好就能用,UI 引导填 cookies / 代理,粘贴歌单就开下 |
| **存量用户**(熟悉 CLI) | UI 能复现所有 CLI 能力,且对大批量任务有进度可视化 |
| **整理者**(下完后做 review) | 在 UI 里直接看匹配报告、对 mismatch 重下、按元数据改名 |

典型一次完整使用:
1. 首次启动 → 配置 cookies + 代理 → 测试连通
2. 编辑/导入歌单 → 测试下 5 首验证环境
3. 全量下载(可断点续传),观察进度
4. 跑匹配校验 → 看分类报告
5. 对 mismatch / warn 类做整理(挪子目录 / 改名 / 重下)
6. 可选:opus→mp3 转码、shuffle_rename 给音箱用

## 3. 功能需求

按"页面/Tab"组织。每条都标注【来源脚本】,说明它对应现有哪个 CLI。

### 3.1 下载(Dashboard / 下载页)【`main.py`】

| # | 能力 | 说明 |
|---|------|------|
| D-1 | **歌单编辑器** | 直接在 UI 编辑 `songs_list.txt` 内容(表格:标题/艺人/原始行),支持增删改、批量粘贴、从 `.txt` 文件导入 |
| D-2 | **测试模式** | "随机抽 N 首"按钮,对应 `--test N`,展示将要下载的列表 |
| D-3 | **全量下载** | 对应 `--all` |
| D-4 | **断点续传** | 对应 `--resume`,显示"已完成 X / 待下载 Y" |
| D-5 | **实时进度** | 总进度条 + 当前并发任务的逐条状态(搜索中/下载中/嵌入元数据中/完成/失败),实时刷新 |
| D-6 | **并发控制** | 滑块或数字框调整 `CONCURRENT_DOWNLOADS`(1~10) |
| D-7 | **停止/暂停** | 停止当前批次(优雅停止:已完成的不丢,未开始的不跑) |
| D-8 | **失败重试入口** | 列出 `failed.json`,支持"全部重试"或"勾选重试" |
| **D-9** | **⭐ 自定义下载目录** | **用户可指定任意输出目录**(默认项目根 `downloads/`)。目录选择器 + 显示当前路径 + "恢复默认"。该值落 `config.user.json` 的 `DOWNLOADS_DIR`,覆盖 `config.py`。`yt-dlp` 的 `-o` 模板用此目录 |
| **D-10** | **⭐ 搜索结果质量标注** | 下载明细表新增「匹配质量 / 置信度」列:综合标题相似度+艺人匹配+类型(song/video)+黑名单/降权词打分,分三档:<br>🟢 **高**(自动下载)/ 🟠 **中**(按策略)/ 🔴 **低**(疑似翻唱/MV/Live/Medley/艺人严重不匹配)。低/中置信度的行用警示色标注原因 |
| **D-11** | **⭐ 存疑候选二次确认** | 当某首歌的"最优候选"置信度非高时,按用户选择的策略处理:<br>① **逐条确认(默认)**:暂停该首,弹层展示 YT 返回的<b>全部候选</b>(标题/频道/时长/类型/标注/分数),用户可选"用第1个"、"我选别的候选"、"跳过"<br>② **存疑直接跳过**:不弹层,标记为 skipped<br>③ **全部自动**:不弹层,直接下,事后去校验页 review<br>策略在下载页顶部可切换,落配置 |
| **D-12** | **待确认队列** | 策略①下产生的 pending 项进独立计数(🟠待确认),可随时从下载页 filter 切到"待确认"集中处理 |

### 3.2 匹配校验(Review 页)【`check_matches.py`】

| # | 能力 | 说明 |
|---|------|------|
| R-1 | **运行校验** | 触发 `check_matches`,读取 `success.json`/`failed.json` |
| R-2 | **分类概览卡片** | 8 类计数卡片(ok / ok_no_artist / warn_alias_likely / warn_partial_artist / warn_no_artist / warn_title_only / warn_title_diff / mismatch + failed) |
| R-3 | **分类明细表** | 每条显示:请求标题/艺人 → 实际标题/艺人、相似度、videoId、文件存在?、磁盘元数据(可选 `--check-files`) |
| R-4 | **筛选与排序** | 按分类筛、按相似度排序、按"文件缺失"筛 |
| R-5 | **行内操作** | 对单条:打开文件所在目录、用浏览器打开 videoId、**强制重下**(删 success 条目后重跑) |
| R-6 | **导出报告** | 导出 `match_report.md`(等价 CLI 默认输出) |

### 3.3 文件整理(Organize 页)【`organize_by_check.py` + `rename_by_metadata.py`】

| # | 能力 | 说明 |
|---|------|------|
| O-1 | **按分类挪文件** | dry-run 预览 → apply,显示"X 个文件将移到 `downloads/{cls}/`",可选移动/复制 |
| O-2 | **按元数据改名** | 选分类(多选:默认 mismatch),dry-run 预览新旧文件名 → apply |
| O-3 | **目录浏览** | 树状展示 `downloads/`,支持手动重命名/删除/打开 |

### 3.4 来源识别(Catalog 页)【`list_non_catalog.py`】

| # | 能力 | 说明 |
|---|------|------|
| C-1 | **扫描正版率** | 触发扫描,显示 catalog / catalog_no_album / non_catalog 三类计数 |
| C-2 | **非编录明细** | 列出 fallback 到普通视频的歌,支持跳转 videoId 人工核对 |

### 3.5 URL 直下(Urls 页)【`download_from_urls.py`】

| # | 能力 | 说明 |
|---|------|------|
| U-1 | **URL 列表** | 粘贴/导入 YouTube URL 列表(每行一个) |
| U-2 | **直接下载** | 跳过搜索,按 URL 下载,实时进度同 D-5 |
| U-3 | **断点续传** | 同 D-4,基于 `url_success.json` |

### 3.6 转码与改名工具(Tools 页)【`opus2mp3.py` + `shuffle_rename.py`】

| # | 能力 | 说明 |
|---|------|------|
| T-1 | **opus→mp3 转码** | 选目录、码率(默认 320k)、是否递归、是否删源;dry-run 预览 → apply,带进度 |
| T-2 | **随机播放改名** | 选目录、前缀类型(number/letter/mixed)、前缀长度、递归;dry-run 预览 → apply,支持 `--restore` 还原 |

### 3.7 设置(Settings 页)【`config.py` + `export_cookies.py`】

**这是用户特别强调的一块。**把所有 `config.py` 项做成可视化表单,分四组:

#### 3.7.1 Cookies 管理【重点】

| # | 能力 | 说明 |
|---|------|------|
| S-C1 | **来源选择** | 三选一:① 手动 `cookies.txt` 文件路径 ② 从浏览器自动提取(`COOKIES_FROM_BROWSER`,下拉选 chrome/firefox/edge/brave/chromium) ③ 不使用 |
| S-C2 | **一键导出** | 触发 `export_cookies.py` 逻辑,把浏览器 cookies 导成项目根 `cookies.txt`,显示导出条数 |
| S-C3 | **手动上传** | 支持用户直接拖拽/选择一个 `cookies.txt` 文件导入 |
| S-C4 | **有效性测试** | 用当前 cookies 配置跑一次"轻量请求"(如 ytmusicapi.search 一首歌),反馈 ✅/❌ + 错误信息 |
| S-C5 | **状态展示** | 显示当前生效的 cookies 来源、文件修改时间、条数 |

#### 3.7.2 网络

| # | 能力 | 说明 |
|---|------|------|
| S-N1 | **代理** | 输入框,支持 `http://`/`socks5://`,空=自动探测;附"测试连通"按钮(请求 YouTube) |
| S-N2 | **⭐ 系统代理自动探测** | **应用自动读取系统代理设置,用户不用在 UI 里重复填**。优先级:`config.proxy`(UI 手填)> 环境变量 `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY` > 系统全局代理设置。探测方式:macOS `scutil --proxy` / Windows 注册表 `HKCU\...\Internet Settings` / Linux `gsettings org.gnome.system.proxy`。yt-dlp 子进程启动时,把探测到的代理同时通过 `--proxy` 显式传 + 注入环境变量兜底。**场景:用户开着 Clash/Surge 的"系统代理"模式,应用直接能用,无需任何配置** |
| S-N3 | **代理状态展示** | 设置页显示"已检测到系统代理: 127.0.0.1:7897"或"未检测到代理(直连)",让用户知道当前实际走没走代理 |
| S-N4 | **连通性诊断** | 一键检测:能否解析 YouTube / ytmusicapi 是否通 / ffmpeg 是否在 PATH / deno 或 node 是否在 PATH |

#### 3.7.3 下载与过滤

| # | 能力 | 说明 |
|---|------|------|
| S-D1 | **格式偏好** | 下拉:opus 优先(默认)/ m4a 优先 / 纯 bestaudio |
| S-D2 | **元数据开关** | 嵌入封面、嵌入元数据(两个 checkbox) |
| S-D3 | **重试策略** | 重试次数、退避序列(可编辑列表) |
| S-D4 | **过滤词编辑器** | SKIP_KEYWORDS / SKIP_ARTIST_KEYWORDS / DEPRIORITIZE_KEYWORDS 三个列表,支持增删、批量粘贴 |
| S-D5 | **时长范围** | 最小/最大秒数(两个 number) |
| S-D6 | **搜索候选数** | `SEARCH_LIMIT` |

#### 3.7.4 路径与持久化

| # | 能力 | 说明 |
|---|------|------|
| S-P1 | **路径展示** | downloads / logs / cache / songs_list 四个路径,只读展示 + "打开"按钮 |
| S-P2 | **保存到 config** | 所有设置改动 → 写回 `config.py`(或新的 `config.user.json`,详见技术选型文档) |
| S-P3 | **重置默认** | 一键恢复 `config.py` 原值 |

### 3.8 帮助中心(Help 页)【新增 · 用户强调】

**用户明确要求:界面里要有详细的使用说明和常见问题处理说明。**
来源:根 `README.md` 的"快速开始/详细用法/FAQ/已知限制/匹配分类体系"——这些知识不能只存在于外部 md,
必须内嵌进应用,让用户不离开应用就能学会使用、能自助排错。

| # | 能力 | 说明 |
|---|------|------|
| H-1 | **快速上手引导** | 首次启动的 4 步引导(配 cookies → 导入歌单 → 测试 5 首 → 全量);也可在帮助页随时重看 |
| H-2 | **功能说明** | 每个页面的"做什么 + 怎么用 + 对应哪个 CLI",图文/截图,按页面组织 |
| H-3 | **匹配分类体系** | 8 级分类(ok/mismatch/warn_*)的含义、触发条件、处理建议,Review 页结果直接可跳转查阅 |
| H-4 | **常见问题 FAQ** | 报错对应处理(见下表),**按报错信息可搜索**;每条含「现象→原因→解决」三段式 |
| H-5 | **故障排查向导** | 环境自检(ffmpeg/deno/cookies/代理/Python 插件)→ 一键诊断 → 给出具体修复步骤与下载链接 |
| H-6 | **上下文帮助** | 页面/按钮旁的 ❓ 图标,点开显示该项的简短说明(Tooltip + "了解更多"跳帮助页锚点) |
| H-7 | **已知限制** | 坦白告知工具边界:含 `-` 艺人名、单字标题、跨语言同曲等情况的精度限制 |
| H-8 | **日志一键导出** | 排错时把 logs/ + 环境信息打包成 zip,方便提 issue |

#### FAQ 必须覆盖的问题(来自根 README + 实际踩坑)

| 报错/现象 | 原因 | 解决 |
|-----------|------|------|
| `Requested format is not available` | 缺 JS 运行时,YouTube 挑战失败 | 装 deno(或配置 node 兜底),附下载链接 |
| `Postprocessing: Supported filetypes for thumbnail embedding...` | webm→opus 重封装没生效 | 检查 Tauri 后端 ffmpeg/yt-dlp 参数顺序 |
| `ytmusicapi songs-search failed` / 搜索空 | 网络/代理问题,或 ytmusicapi 旧 | 配代理;或升级/启用高精度插件 |
| 中国大陆连不上 | 需代理 | Settings→网络填代理 |
| 下载到的歌不对(mismatch) | YT 搜索返回了翻唱/MV/medley | Review 页看分类,点"重下"换 videoId |
| 想要 mp3 而非 opus | 默认保留原始流 | Tools 页转码(320k,会二次有损) |
| 强制重下某首歌 | — | Review 页"重下",或删 success.json 条目 |
| 不知道下的是不是正版 | — | Catalog 页扫描,或看 `Provided to YouTube by` 签名 |
| cookies 在 Linux 失败 | GNOME Keyring 损坏 | 改用 cookies.txt 文件方式 |
| 安装包提示缺 ffmpeg/deno | 非内置,需自备 | 帮助页给各平台安装命令 |

## 4. 非功能需求

| 维度 | 要求 |
|------|------|
| **跨平台** | Windows / macOS / Linux 三端原生可用,首选"一份代码三端跑" |
| **分发** | 普通用户能拿到一个安装包/dmg/exe/AppImage,不需要自己装 Python(目标,见选型) |
| **性能** | 1000+ 首歌单编辑不卡;并发下载时 UI 不冻结 |
| **实时性** | 下载进度刷新延迟 < 1s |
| **可观测** | 任何操作失败都有可复制的错误信息,不弹"未知错误"了事 |
| **不破坏 CLI** | UI 与 CLI 共存,UI 只是壳;底层 `process_song` 等函数不变 |
| **依赖收敛** | UI 框架不引入与现有 Python 栈冲突的重依赖 |

## 5. 约束与边界

**做什么:**
- 给现有 11 个脚本套 UI,新建一个跨平台桌面应用。
- cookies / 代理 / 过滤词等配置全部可视化。

**不做(首版):**
- 不做云同步、不做账号系统。
- 不重写下载内核(yt-dlp / ytmusicapi 仍是内核)。
- 不做音频播放器(首版只做"打开所在目录",不内置播放)。
- 不做移动端。

**继承的已知限制(来自根 README):**
- 下载结果不保证 100% 准确(66% ok / 27% alias / 6% warn / 1.3% mismatch)。
- 含 `-` 的艺人名、单字标题、跨语言同曲仍需人工 review——UI 只是把 review 做得更顺手,不消除它。

## 6. 验收标准(首版 MVP)

1. ✅ 能在 Win/macOS/Linux 三端启动,无需用户配 Python 环境(分发形态见选型)。
2. ✅ Settings 页可配置 cookies(三种来源)+ 代理,并能"测试有效性"。
3. ✅ 下载页能跑 `--test N` 和 `--all --resume`,带实时进度。
4. ✅ Review 页能跑匹配校验并展示 8 类分类 + 明细。
5. ✅ Organize 页能 dry-run + apply "按分类挪文件" 和 "按元数据改名"。
6. ✅ Tools 页能跑 opus→mp3 转码。
7. ✅ 所有长任务有进度、可取消、失败有可复制错误。
8. ✅ 底部日志面板实时显示 logging 输出。
